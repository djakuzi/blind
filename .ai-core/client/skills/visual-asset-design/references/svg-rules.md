# Правила построения SVG

## Основа

- Пиши SVG руками как код. Не подменяй его растром в `<image>` и не выдавай автоматическую векторизацию за качественный SVG.
- Обязательно: `xmlns`, `viewBox`. viewBox задаёт логические координаты, видимый размер задаёт CSS/контейнер.
- Сначала геометрия: собери форму из простых фигур (rect, circle, line, polygon), потом переводи в path, если нужно.
- Координаты — на сетке (целые или .5 для обводок нечётной толщины), округление до 1–2 знаков.
- Общие ресурсы (градиенты, clipPath, mask, filter) — в `<defs>`, с уникальными префиксными `id`.
- Без метаданных редактора, пустых path, комментариев-заглушек и TODO. Короткие комментарии, объясняющие конструкцию, допустимы (как в иконках `connectionType`).

## Иконки

- Держи viewBox, поля и вес линий как у соседей в группе (см. `project-assets.md`).
- Один вес обводки в пределах набора. Если иконки из одного набора стоят рядом, их визуальный вес должен совпадать.
- Для обводок: `stroke-linecap` и `stroke-linejoin` выбирай под характер набора и держи одинаковыми.
- Тонкие детали исчезают на 16–24 px: проверяй самый маленький реальный размер.
- Иконка внутри кнопки — без собственных лишних полей, если соседние иконки обрезаны по границам.

## Центрирование и оптический баланс

- Геометрический центр ≠ оптический. Треугольник «play», стрелки, асимметричные фигуры нужно смещать к визуальному центру тяжести — проверяй на рендере, а не в цифрах.
- Одинаковые поля со всех сторон, если нет причины. Стенд показывает поля и смещение центра в единицах viewBox.
- Круги и квадраты одинаковой ширины выглядят разными по размеру: круг делают чуть больше.
- Симметричные формы — действительно симметричны: проверь координаты зеркальных частей.

## Цвет и темы

- Цвета — только из palette tokens (`src/app/shared/styles/tokens/colors.css`).
- Вариант для другой темы — не обязательно инверсия. Проверь контраст и сохранение характера формы.
- Просили поменять только цвет — геометрия не меняется.

## Эффекты

- Плоско по умолчанию. Градиенты, тени и фильтры — только когда они несут смысл.
- Тяжёлые `filter` (blur, turbulence) дорого рендерятся, особенно в мобильном WebView и при анимации. Для игровых ассетов — с осторожностью.
- Анимация — предпочтительно CSS; учитывай `prefers-reduced-motion`.

## Доступность

- Декоративная графика: `aria-hidden="true"` (так в проекте по умолчанию).
- Смысловая графика: подпись через `alt` у `AppIcon` (идёт в `aria-label`), текст — через Locale.

## Перед сдачей

- [ ] `xmlns` + `viewBox`, нет `<script>`, `on*`, внешних ссылок, `<image>`
- [ ] `id` уникальны с префиксом
- [ ] Пара `-dark`/`-light` совпадает по геометрии
- [ ] Цвета из palette tokens
- [ ] Отрендерено на стенде, центр и поля проверены, сравнено с соседями/эталоном — если пользователь согласился на проверку; иначе в отчёте: «рендером не проверено»
- [ ] Если файл добавлен/переименован — запущен `npm run app:generate:icons-assets`
