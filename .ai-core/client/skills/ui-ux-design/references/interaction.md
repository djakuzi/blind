# Состояния, motion и обратная связь

## Состояния контролов

Для каждого нового контрола определи только нужные состояния:

Default, Hover (если применимо), Focus, Pressed, Active, Selected, Disabled, Loading, Success, Error, Empty.

Продумай: нажатие, удержание, перетаскивание, выбор, отмену, подтверждение, возврат назад, ошибки. Сложное действие должно быть понятно без длинной инструкции.

Перед созданием своего механизма проверь готовые: `interaction/hold`, `interaction/slider`, `interaction/overlay`, `effects/*` в `src/app/shared/components`.

## Motion

- Motion объясняет иерархию, причину и следствие, переход между состояниями. Не декорирует.
- Несколько осмысленных переходов лучше постоянной микроанимации.
- Сильная анимация — только для смены состояния, награды, опасности, онбординга.
- Анимация в ответ на действие игрока (открыл, раскрыл, подтвердил) уместна, если показывает, что изменилось.
- Не замедлять основные действия.
- Длительности и easing — из `src/app/shared/styles/tokens/motion.css`. Технические значения конкретной анимации могут оставаться локальными (см. «Когда нужен новый token» в `cssStyle.md`).
- `prefers-reduced-motion` — для всех неключевых анимаций (примеры уже есть в `utilities/interactive.css`).
- Текущие анимации проекта не считаются утверждёнными.

## Звук и haptic

- Обратная связь — это визуал, звук и haptic вместе как одно событие.
- Звуки назначаются по смыслу взаимодействия, а не всем кнопкам подряд.
- Правила звукового языка — `docs/client/audio/sections/ui-audio.md`. Воспроизведение из Vue — по правилам `docs/client/interface/index.md`.

## Оценка удобства

Оценивай отдельно:

- контраст и читаемость;
- иерархию;
- размер целей;
- различимость состояний;
- доступность с клавиатуры и touch;
- возможность отмены;
- защиту от случайных действий;
- количество лишних шагов.

Красота и удобство связаны, но оцениваются отдельно.
