# Принципы motion

## Выбор средства по смыслу

| Задача | Средство |
|---|---|
| Непрерывность, связь элементов | общий элемент, FLIP, пространственное движение |
| Фокус и глубина | ограниченный blur, тень, свет, затемнение фона |
| Появление и раскрытие | маски, `clip-path`, обрезка |
| Материал и энергия | цвет, позиция градиента, текстура — если позволяет стиль и производительность |
| Состояние и отклик | минимальное изменение, после которого причина и результат очевидны |

Не складывай приёмы ради зрелищности. Одна сильная идея в главном моменте и тихие поддерживающие состояния — обычно достаточно.

## Тайминг

Ориентиры и tokens проекта (`tokens/motion.css`):

| Длительность | Использование | Token |
|---|---|---|
| ~100–150 мс | мгновенный отклик (нажатие, hover) | `--app-motion-duration-fast` (140) |
| ~150–220 мс | обычная смена состояния | `base` (160), `medium` (180), `slow` (220) |
| ~220–500 мс | раскладка, оверлей, переход экрана | `slower` (320); переход экрана сейчас 230 мс |
| ~500–800 мс | осознанный авторский вход | только для главного момента |

- Уход быстрее появления (так уже сделано в `AppSwapTransition`: enter — `medium`, leave — `fast`).
- Длинный отклик ощущается как задержка ввода.
- Каскад (stagger) — только когда список появляется как список, общая задержка ограничена (ориентир — до ~300 мс на весь каскад).

## Easing

- Вход: `--app-motion-ease-enter` (уверенное замедление `cubic-bezier(0.22, 1, 0.36, 1)`).
- Уход: `--app-motion-ease-exit` (ускорение).
- Смена цвета/прозрачности: `--app-motion-ease-default`.
- Упругость (overshoot, back) — только для «поп»-откликов и наград, не по умолчанию. Bounce и elastic — не рефлекторно.

## Hover и нажатие

- Hover — только `@media (hover: hover) and (pointer: fine)`. На touch hover нет.
- Hover-движение не сдвигает соседей и не уводит элемент из-под курсора: двигай внутренний слой, а не сам элемент с hit-area. Небольшое масштабирование (как `AppInteractionScale`, 1.015) допустимо.
- Нажатие (`:active`) — быстрее hover (в проекте 90 мс), отклик сразу.
- Отложенный показ подсказки — задержка только на вход, уход без задержки.

## Reduced motion

- `prefers-reduced-motion: reduce` — меньше и мягче движения, а не полное отключение любой обратной связи.
- Убирай или сокращай пространственное движение (сдвиги, масштаб, параллакс), но сохраняй смысловые изменения: прозрачность, цвет, смену состояния.
- Подтверждение действия должно оставаться заметным.
- Бесконечные декоративные циклы при reduced motion останавливаются; вне экрана и в скрытой вкладке — тоже.
- В проекте сейчас часто используется `transition: none` при reduced motion — это допустимо, если состояние всё равно видно мгновенно. Проверяй, что ничего не теряется.

## Признаки шаблонной анимации

- Fade-and-slide-up на каждом блоке экрана.
- Hover-подъём на каждой карточке.
- Параллакс и reveal при скролле без смысла.
- Постоянная микроанимация, конкурирующая с главным.
- Анимация, заметная только потому, что её «добавили для полировки».

## Критерии готовности

- Главный момент (если есть) специфичен для Blind и этого экрана.
- Каждая поддерживающая анимация объясняет отклик, состояние или связь.
- Повторное и прерванное действие ведут себя корректно.
- Desktop, mobile и клавиатура остаются удобными.
- Reduced motion сокращает движение, не стирая обратную связь.
- Дорогие эффекты плавны на целевых устройствах.
- Если убрать анимацию — потеряется смысл или характер, а не просто украшение.
