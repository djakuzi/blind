# Игровой UI: правила

Методика адаптирована под Blind (Vue + DOM-интерфейс поверх будущего игрового поля).

## Игровое поле и HUD

- Игровое поле рисуется отдельно (canvas/WebGL — технология ещё не выбрана). Текстовый и интерактивный UI — в DOM, то есть во Vue-компонентах. Не переносить меню и текст внутрь игрового рендера, если DOM проще и доступнее.
- Во время матча: один основной кластер HUD и максимум один небольшой вторичный. Ориентир — постоянный HUD занимает не больше ~20–25% экрана.
- Центр и нижняя середина экрана свободны во время обычной игры.
- Подсказки — контекстные и временные (появились → исчезли), а не постоянные панели.
- Длинные тексты, правила, полный список управления — за паузой, drawer или отдельным экраном.
- Оверлеи поверх движения должны читаться: подложка, контраст, аккуратный blur.
- Критичная для игры информация — первой по иерархии, вторичные инструменты — второй, редкие настройки — в меню.
- HUD обновляется по событиям/реактивному состоянию, а не опросом каждый кадр. При подключении сразу показывается текущее значение.

## Меню и экраны вне матча

- Меню должно ощущаться частью мира игры, а не админкой.
- Не одинаковые карточки с одинаковыми тенями по всем краям. Иерархия: один главный элемент, остальные тише.
- Первый экран должен вести к игре за пару секунд: главное действие очевидно.
- Не раскрывать всё сразу при первом открытии (правила, настройки, подсказки, лор).

## Стек экранов и модалки

- Экраны и оверлеи — это стек, а не набор булевых флагов (`isPaused`, `inSettings`, `confirmOpen` ломаются на третьем оверлее).
- Только верхний экран принимает ввод. Под модалкой ввод и фокус заблокированы.
- При открытии экрана фокус ставится на один осмысленный элемент.
- При закрытии верхнего экрана фокус возвращается на тот элемент, с которого его открыли.
- Фокус не «убегает» из модалки на элементы под ней.
- Во время матча открытое меню/модалка должна блокировать игровой ввод.
- Пауза не должна замораживать анимации самого меню паузы.
- Перед изменением проверь существующие механизмы: `src/app/overlay`, `src/app/providers`, `src/app/shared/components/interaction/overlay`.

## Ввод

- Touch, мышь, клавиатура — равноправны с самого начала.
- Hover не может быть единственным способом показать информацию или действие.
- Видимый focus-стиль, отличный от hover.
- Опасные и необратимые действия защищены от случайного нажатия (подтверждение, удержание, отмена).
- Геймпад можно закладывать в структуру (стек, фокус), но не заявлять поддержку без проверки.

## Доступность (минимум)

- Цвет — не единственный сигнал (красный = опасность): добавляй форму, иконку или текст.
- Контраст текста, несущего игровую информацию, — не ниже 4.5:1; крупного текста и ключевых визуальных элементов — не ниже 3:1.
- Размер текста — только через typography tokens. Проверяй читаемость самого мелкого токена на телефоне в landscape.
- Длинные переводы (немецкий примерно на 30% длиннее английского) не должны ломать раскладку: контейнеры растут по содержимому.
- Reduced motion — для всех неключевых анимаций.

## Анти-шаблоны

- Дашборд вместо игрового интерфейса.
- Плоская «заглушечная» стилизация без характера.
- Плотные оверлеи, закрывающие поле.
- Большие заголовки или абзацы текста поверх живой игры.
- Одинаковые панели по всем краям экрана.
- Анимация на каждом элементе.
- Игровой ввод, который продолжает работать под модалкой.
