# Правила работы с git

Ветки, порядок работы и коммиты.

## Ветки

Формат: `[тип]/[описание до трёх слов]`. Если у задачи есть номер, добавьте его перед описанием: `[тип]/[номер задачи]-[описание до трёх слов]`. Слова в описании пишутся строчными латинскими буквами и цифрами через дефис.

| Ветка | Назначение | Создаётся от |
|---|---|---|
| `main` | production | — |
| `development` | stage | `main` |
| `feature/` | новая функциональность | `development` |
| `bugfix/` | исправление | `development` |
| `hotfix/` | срочное исправление production | `main` |

## Порядок работы

1. Обновить `development`: `git fetch && git pull`.
2. Создать ветку от `development` или влить `development` в свою ветку.
3. Внести изменения.
4. Открыть реквест своей ветки в `development`.

## Коммиты

Ориентир — [How to Write a Git Commit Message](https://cbea.ms/git-commit/).

1. Заголовок — до 50 символов.
2. Повелительное наклонение: «Add», «Fix», «Move», а не «Added».
3. Тело при необходимости объясняет, что и зачем изменено.
