# Правила документации

Как писать и раскладывать документацию в `docs`.

## Структура `docs`

Каждый раздел устроен одинаково:

| Что | Назначение |
|---|---|
| `index.md` | Что описывает раздел и ссылки на его документы |
| `rules/` | Общие правила работы в этой теме |
| `sections/` | Описания конкретных сущностей или подтем |

Новый документ кладётся в раздел своей темы. `rules/` и `sections/` создаются только когда в них есть файлы.

## Как писать

1. **Сначала суть.** Правило — одно-два предложения. Объяснение добавляется, только если без него правило непонятно.
2. **Без воды.** Не повторять одно и то же, не пересказывать очевидное из кода, не дублировать другие документы.
3. **Структура вместо абзацев.** Заголовки разделов и подразделов, нумерованные списки для правил, таблицы для сравнений.
4. **Один документ — одна тема.** Если тема разрастается, она выносится в отдельный документ.

## Примеры

1. Пример добавляется, только если без него принцип непонятен.
2. Пример абстрактный: условные имена (`AppParent`, `AppChild`, `tExampleValue`) показывают принцип, а не конкретный код проекта.
3. Реальные компоненты, функции и значения в примеры не берутся: они меняются, и пример начинает врать.
4. Реальные пути допустимы как ориентир — где лежит, что запустить, что генерируется. Если путь меняется, документ обновляется вместе с кодом.

## Связи между документами

Раздел «Связанные разделы» **необязателен** и чаще всего не нужен.

Ссылка добавляется, только если документ опирается на понятие или правило из другого документа и без него текущие правила нельзя понять или применить. Например, правила CSS опираются на модель масштаба UI.

Ссылка не добавляется:

1. на документы того же раздела — их уже перечисляет `index.md`;
2. по принципу «тема рядом» или «где это ещё используется»;
3. если ссылка уже есть в тексте документа.

Каждая оставленная ссылка объясняет, **что** она помогает понять в текущем документе:

```md
## Связанные разделы

- [Название](./path.md) — что именно без этого не понять.
```

## Шаблон документа

```md
# Название

Одно-два предложения: что описывает документ.

## Тема

1. Правило.
2. Правило.
```

«Связанные разделы» добавляются в конец только по правилу выше.
