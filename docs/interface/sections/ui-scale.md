# Масштабирование интерфейса

Модель размеров UI: один общий масштаб, который зависит от ширины и высоты экрана.

## Принцип

1. Весь UI масштабируется одним значением — через root font size. Отдельных `scaleX` и `scaleY` нет.
2. Масштаб влияет на размеры (`rem`), а раскладка занимает реальный viewport: `%`, `dvh`, flex и позиционирование работают как обычно. Виртуального canvas нет.

## Формула

Задаётся в `src/app/shared/styles/tokens/scale.css`:

```css
--app-root-font-size-base: min(<по ширине>vw, <по высоте>dvh);
--app-root-font-size: calc(var(--app-root-font-size-base) * var(--app-scale));
```

1. Берётся меньший из двух кандидатов: узкие и квадратные экраны (4:3) ограничены шириной, широкие (16:9, 21:9) — высотой.
2. Переход между режимами непрерывный, без media queries под устройства.
3. Design reference — viewport `2560 × 1318`: на нём оба кандидата дают одинаковый размер.

## Пользовательский масштаб

`--app-scale` — настройка размера интерфейса (`small`, `default`, `large`). Значения — в `appScale.contract.ts`.

1. Применяется один раз в формуле.
2. Не используется для определения типа устройства.
3. Не применяется повторно в tokens и компонентах.

## Размеры в компонентах

1. Размеры задаются в `rem` и через tokens — тогда текст, отступы, радиусы и controls масштабируются вместе.
2. Свои коэффициенты масштаба в компонентах не добавляются.
3. Отдельная scale-логика под mobile, tablet, desktop или пропорции не создаётся.
4. Компонент не помещается — правится его раскладка, а не глобальная формула. Responsive-правила — только там, где ломается композиция.

## Safe area

Отдельная система: компоненты используют `--app-safe-area-top`, `-right`, `-bottom`, `-left`, а не `env(safe-area-inset-*)`.

## UI scale и render scale

| | UI scale | Render scale |
|---|---|---|
| Влияет на | CSS-интерфейс: меню, настройки, HUD, кнопки, текст, overlays | качество рендера игрового поля |
| Зависимость | — | не влияет на CSS tokens |
