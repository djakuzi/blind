# Правила взаимодейтсвия с Git

## Правила именования веток
Формат названия ветки:  
`[тип ветки]/[номер задачи]-[краткое описание, до трех слов]`

Существует 6 видов веток:
* `production` - Ветка без типа, Production вида
* `development` - Ветка без типа, Stage вида, создаваемая от `production` ветки
* `feature/` - Ветки с типом фича, создаваемые от `development` ветки
* `bugfix/` - Ветки с типом баг-фикс, создаваемые от `development` ветки
* `hotfix/` - Ветки с типом важный баг-фикса, создаваемые от `production` ветки
---
* Ветка должна создаваться от ветки **production**
Например:
```bash
BRANCH=000000_catalog && git fetch origin && git checkout -b $BRANCH origin/production && git push --set-upstream origin $BRANCH
```

## Правила именования коммитов
Ориентиром послужит данная статья [cbea.ms](https://cbea.ms/git-commit/).  
Стоит выделить из нее:
* Язык хоть и предпочтителен английский, но ясность сообщения должна стоять во главе, поэтому лучше грамотно и понятно расписать на русском, нежели пытаться коряво изложить на английском
* Ограничивайте заголовок 50 символами
* Пишите заголовок с заглавной буквы
* Не ставьте точку в конце заголовка
* Отделяйте заголовок от тела пустой строкой
* Используйте повелительное наклонение в заголовке _(словно вы говорите git add/добавь, git modify/измени и т.д.)_
* Переходите на следующую строку в теле на 72 символах
* В теле отвечайте на вопросы **что** и **почему**, а не **как**
