# Правила взаимодейсnвия с Git

## Правила именования веток
Формат названия ветки:  
`[тип ветки]/[номер задачи]-[краткое описание, до трех слов]`

Существует 6 видов веток:
* `main` - Ветка без типа, Production вида
* `development` - Ветка без типа, Stage вида, создаваемая от `main` ветки
* `feature/` - Ветки с типом фича, создаваемые от `development` ветки
* `bugfix/` - Ветки с типом баг-фикс, создаваемые от `development` ветки
* `hotfix/` - Ветки с типом важный баг-фикса, создаваемые от `production` ветки
---

## Порядок работы
1. Делаем 
`git fetch && git pull` на ветке **development** с учетом тега последнего релиза
2. Создаем новую ветку или мерджим **development** ветку в свою текущую ветку
3. Вносим изменения в код
4. По завершению работ, создаем реквест своей ветки в ветку **development**

## Правила именования коммитов
Ориентиром послужит данная статья [cbea.ms](https://cbea.ms/git-commit/).  
Стоит выделить из нее:
* Ограничивайте заголовок 50 символами
* Используйте повелительное наклонение в заголовке _(словно вы говорите git add/добавь, git modify/измени и т.д.)_
