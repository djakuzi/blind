# Правила Generate

Правила описывают соглашения для генераторов проекта, которые лежат в `scripts/generators` и запускаются через `npm scripts`.

## Именование команд

1. Команда генератора в `package.json` должна начинаться с префикса `app:`.
2. Рекомендуемый формат имени команды: `app:generate:<entity>`.
3. Имя команды должно отражать, что именно генерируется.

Примеры:

- `app:generate:icons`
- `app:generate:colors`
- `app:generate:node-docs`

## Размещение генераторов

1. Скрипты генераторов должны лежать в `scripts/generators/`.
2. Один генератор должен отвечать за одну понятную задачу.
3. Не нужно объединять несколько несвязанных генераций в один большой скрипт без необходимости.

## Источник данных

1. У генератора должен быть явный источник данных.
2. Если генератор синхронизирует данные, в проекте должен быть один source of truth.
3. Генератор не должен дублировать данные вручную в нескольких местах, если их можно взять из одного источника.

Примеры источников:

- `package.json`
- `src/app/styles/tokens/*`
- `src/assets/*`

## Правила изменения файлов

1. Генератор должен изменять только те файлы, которые относятся к его задаче.
2. Генератор не должен затрагивать посторонние файлы.
3. Если генератор обновляет текстовые файлы, область изменения должна быть ограничена маркерами, шаблоном или предсказуемым участком структуры.
4. Ручной текст вокруг сгенерированных участков не должен ломаться после запуска генератора.

## Предсказуемость

1. Повторный запуск генератора без изменения входных данных должен давать тот же результат.
2. Генератор должен быть детерминированным.
3. Генератор не должен зависеть от случайного порядка файлов, локального состояния терминала или ручных действий во время запуска.

## Логирование и ошибки

1. Генератор должен понятно сообщать, что именно он обновил.
2. Если генератор ничего не нашел для изменения, это должно быть явно отражено в выводе.
3. Если отсутствует обязательный источник данных, генератор должен завершаться с ошибкой.
4. Ошибка генератора должна быть понятной и указывать, что именно не найдено или настроено неверно.

## Документация

1. Каждый генератор должен быть описан в `docs/generators`.
2. Для нового генератора нужно создать отдельный файл в `docs/generators/sections/`.
3. В документации генератора нужно указать:
   - что он генерирует;
   - откуда берет данные;
   - как запускается;
   - какие файлы обновляет;
   - когда его нужно использовать.
4. Если у генератора есть специальные маркеры, флаги или режимы запуска, это тоже должно быть описано в документации.

## Когда использовать генераторы

1. Генераторы используются для повторяемых изменений, где важно единообразие результата.
2. Если структура может быть вычислена автоматически, предпочтительно использовать генератор, а не ручное редактирование.
3. Если изменение одноразовое и не дает устойчивого проектного паттерна, отдельный генератор создавать не нужно.
