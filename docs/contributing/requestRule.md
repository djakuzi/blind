# Правила создания реквестов

## Правила реквестов на слияние
* Лучше всего использовать стандартный шаблон и редактировать его по необходимости
* Заголовок реквеста должен следовать заголовку основного коммита и/или улучшать его
* В заголвоке реквеста можно указывать в формате: номер задачи из Битрикс 24, точка, после уже заголовок реквеста, например: `123456. Заголовок реквеста`
* Можно в описание реквеста включить тело из коммитов, входящих в реквест
* После **или** вместо основного описания, дальше в теле должно следовать описание для списка изменений [CHANGELOG.md] формат:
```markdown
### Добавлено
Описание для новых функций.
### Изменено
Описание для изменений в существующей функциональности.
### Устарело
Описание для функций, которые скоро будут удалены.
### Удалено
Описание для удалённых на данный момент функций.
### Исправлено
Описание для любых исправлений багов.
### Безопасность
Описание на случай уязвимостей.
```
Где:  
**Описание** - понятное изменение того, что сделано одним из коммитов.
Область и описание должны быть написаны не техническим языком, чтобы изменения мог понять любой человек, например _менеджер проекта_ или _тестировщик_
* Если реквест не готов к слиянию с **development** веткой, т.к. работы еще ведутся, то в заголовок обязан начинаться с **Draft: **
* По готовности реквеста к ревью или выкату, к реквесту должен быть назначен ответственный с правами **maintainer** или выше
