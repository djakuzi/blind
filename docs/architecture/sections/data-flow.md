# Архитектура и data-flow

Проект построен по слоистой схеме:

1. `app` - точка входа, глобальная инициализация, роутинг, провайдеры, layout'ы и app-level setup.
2. `views` - страницы, которые рендерятся роутером.
3. `features` - пользовательские сценарии и составные UI-блоки.
4. `stores` - состояние предметных областей.
5. `domain` - бизнес-модели, API-сервисы, мапперы и логика предметной области.
6. `shared` - общие компоненты, утилиты, типы, конфиг, API-клиент и вспомогательные библиотеки.

## Назначение папок

### `app`

Здесь лежат:

- `main.ts` - bootstrap приложения;
- `router` - корневой роутер и guards;
- `layouts` - глобальные layout-компоненты;
- `providers` - глобальные провайдеры;
- `setup` - запуск интеграций вроде Sentry, push, deep links, status bar;
- `deepLinks` - работа с deep link'ами.

### `views`

1. Роутовые страницы.
2. Тонкие экраны, которые собирают данные и передают их в `features`, `stores` и `domain`.

### `features`

1. Сценарии пользователя.
2. Составные блоки интерфейса.
3. Логика, которая связывает экран, store и доменную модель.

### `stores`

1. Состояние конкретных областей приложения.
2. Actions и вычисляемые поля.
3. Подключение к `domain`-логике и API.

### `domain`

1. Доменные модели.
2. API-сервисы.
3. DTO-мэпперы.
4. Бизнес-правила, которые не завязаны на конкретный экран.

### `shared`

1. Переиспользуемые UI-компоненты.
2. `config` для чтения `env` и сборки runtime-конфига.
3. Общие API-утилиты, типы, хелперы и библиотеки.

## Data-flow

Поток данных в приложении обычно такой:

1. `main.ts` инициализирует `Pinia`, `router` и глобальные setup-процессы.
2. `shared/config` читает переменные окружения и собирает runtime-конфиг.
3. `app/setup/*` подключает Sentry, push, deep links, status bar и другие интеграции.
4. Роутер открывает нужный `view` и layout.
5. `view` вызывает `feature`, `store` или `composable`.
6. `store` дергает action.
7. `action` обращается в `domain/api` или `shared/api`.
8. `api service` получает ответ, маппит DTO в доменную модель.
9. `store` обновляет состояние.
10. UI автоматически перерисовывается по новым данным.

## Базовые правила

1. Глобальная логика должна жить в `app`.
2. Страница не должна содержать тяжелую бизнес-логику.
3. Данные с API должны проходить через `domain`-слой.
4. Переиспользуемые части выносятся в `shared`.
5. Сценарии пользователя держатся в `features`, а состояние - в `stores`.
