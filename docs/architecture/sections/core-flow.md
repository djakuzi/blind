# Архитектура core-слоя

`src/core` — базовая инфраструктура, которая не зависит от экранов и игровой логики.

## Части `core`

| Часть | Отвечает за | Не должна |
|---|---|---|
| `lib` | маленькие независимые утилиты и преобразования | зависеть от Vue, app, игры, SDK |
| `platform` | работу с Web, Capacitor и Electron | — |
| `media` | типизированный доступ к generated-реестрам ассетов | отвечать за воспроизведение и UI |
| `http` | транспорт: запросы, middleware, timeout, parsing, ошибки | знать о конкретных API приложения |
| `app` | универсальные механизмы запуска и lazy-маршрутов | знать о конкретных модулях и views приложения |

1. Конкретные API-клиенты и endpoints живут выше `core`.
2. Получение ресурса — `media`, его использование — `platform/tool`. Например, звук берётся из `MediaAudio`, а играет через Tool аудио.

## Platform

| Часть | Назначение |
|---|---|
| `adapter` | выбор реализации под текущую среду |
| `runtime` | определение среды (`web`, `mobile`, `desktop`), платформы, доступ к Electron bridge, общие helpers среды |
| `tool` | публичные инструменты (звук, хранилище, вибрация…) и их реализация |
| `type.ts` | общие типы результата, значения и подписки |

### Главная граница

```text
tool → runtime   разрешено
runtime → tool   запрещено
```

1. `runtime` описывает только среду и не реализует инструменты.
2. Общий helper в `runtime` оправдан, только если им пользуются несколько инструментов или сам runtime.

### Tool

Tool владеет инструментом целиком: публичный API, общая семантика, состояние, выбор adapter, реализации под платформы, свои helpers и engines.

| Файл / папка | Назначение |
|---|---|
| `index.ts` | публичная точка входа, выбор adapter |
| `tool.ts` | общий API, состояние, orchestration |
| `type.ts` | контракт Tool и adapter |
| `adapters/` | реализации для сред |
| `helpers/`, `engines/` | внутренние части, если нужны |
| `const.ts` | константы инструмента |

1. Platform-specific код, нужный только одному инструменту, живёт в его Tool.
2. Общая логика не дублируется между adapters — она в `tool.ts` или helpers этого Tool.
3. Не каждому Tool нужны все папки.

### Electron и Tool

1. Electron plugin даёт только то, что требует main process или privileged API.
2. Tool остаётся владельцем инструмента; desktop adapter обращается к plugin через runtime bridge.
3. Plugin не повторяет весь API Tool.

## Правила

1. Прикладной код обращается к платформе через `core/platform/tool`, а не к SDK напрямую.
2. Изменилась архитектурная граница или публичный platform API — документация обновляется вместе с кодом.
