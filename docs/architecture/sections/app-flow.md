# Архитектура и app-flow

Раздел описывает устройство `app`-слоя: bootstrap приложения, роутинг, layout-компоненты, глобальные провайдеры, app-level stores и глобальные стили.

## Назначение папок в `src/app`

### `layouts`

Здесь лежат layout-компоненты приложения.

- `LayoutRoot.vue` - корневая layout-обертка для дерева маршрутов.
- `LayoutBase.vue` - базовая layout-обертка для экранов приложения.
- `layouts/components/*` - локальные layout-компоненты и контейнеры, которые используются для построения экранов.

### `providers`

Глобальные app-level провайдеры интерфейса.

Сюда относятся компоненты уровня:

- `ProviderBottomSheet.vue`
- `ProviderDialog.vue`
- `ProviderToast.vue`

### `router`

Маршрутизация приложения.

Здесь лежат:

- `index.ts` - создание корневого router instance;
- `sections/*` - отдельные секции маршрутов (`menu`, `game`, `settings`);
- `constants/route.const.ts` - имена и ключи маршрутов;
- `types/vue-router.d.ts` - расширения типов `vue-router`.

### `stores`

App-level состояние, доступное на уровне экранов и общего интерфейса.

Сейчас в `app/stores` лежат store-модули:

- `settings`
- `user`
- `game`

Если состояние нужно для работы экранов, роутинга, UI-режимов или общих сценариев приложения, его допустимо держать в `app/stores`.

### `styles`

Глобальные стили приложения.

Здесь находятся:

- `index.css` - точка входа для app-стилей;
- `core/*` - reset, base и fonts;
- `tokens/*` - глобальные дизайн-токены приложения.

### `view`

Роутовые экраны верхнего уровня.

Сейчас это:

- `ViewMenu.vue`
- `ViewGame.vue`
- `ViewSettings.vue`

Эти компоненты открываются роутером и собираются поверх `layout`-слоя.

## App-flow

Поток управления в `app`-слое обычно такой:

1. `src/main.ts` создает Vue-приложение.
2. В `main.ts` подключается `Pinia`.
3. В `main.ts` подключается `router` из `src/app/router`.
4. `App.vue` подключает глобальные стили `src/app/styles/index.css` и отдает управление `RouterView`.
5. Корневой router из `src/app/router/index.ts` открывает `rootRoute`.
6. `rootRoute` использует `LayoutRoot.vue` как корневую layout-обертку.
7. Внутри `rootRoute.children` выбирается нужная секция маршрута: `menu`, `game` или `settings`.
8. Секция маршрута использует `LayoutBase.vue` как базовую app-layout.
9. Внутри `LayoutBase.vue` рендерится конкретный экран из `src/app/view`.
10. Экран использует локальные layout-компоненты, контейнеры, stores и app-level UI-инфраструктуру.

## Базовые правила

1. Все, что относится к запуску и каркасу приложения, должно жить в `app`.
2. Роутинг и layout-уровень не должны содержать тяжелую предметную бизнес-логику.
3. Экран должен оставаться точкой сборки UI, а не превращаться в глобальный orchestrator всего приложения.
4. Глобальные UI-провайдеры должны оставаться в `app/providers`.
5. App-flow должен описывать только app-level структуру и правила без ухода в другие архитектурные разделы.
