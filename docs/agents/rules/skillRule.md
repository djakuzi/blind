# Правила Skills

Где лежат skills проекта, как они подключаются к агентам, как их писать и когда обновлять.

Skill — папка с `SKILL.md` (инструкция для агента) и дополнительными материалами. Агент подключает skill сам, когда задача подходит под его описание, или по явному вызову.

## Где лежат

Единственный источник — `.ai-core`. У каждого приложения свой плагин: `.ai-core/<приложение>` → `blind-<приложение>`. В `.claude`, `.agents`, `.codex` — только настройки подключения.

```text
.ai-core/
├── .claude-plugin/marketplace.json   marketplace blind-local со всеми плагинами
└── client/                           плагин blind-client
    ├── .claude-plugin/plugin.json    для Claude Code
    ├── .codex-plugin/plugin.json     для Codex
    └── skills/<name>/
        ├── SKILL.md                  главный файл
        ├── references/               подробности, читаются по необходимости
        └── tools/                    вспомогательные файлы, если нужны
```

Пути в skill приложения: к коду — от папки приложения (`apps/client`), к документации и `.ai-core` — от корня репозитория.

Новое приложение получает свою папку `.ai-core/<приложение>`, запись в обоих marketplace и включение плагина в `.claude/` и `.codex/` своего приложения.

Плагин приложения включается только в папке этого приложения. Корневой `.codex/config.toml` плагины не включает: Codex читает его и в сессиях других приложений. Корневой `.claude/settings.json` может включать плагины для сессий из корня — Claude читает настройки только из папки запуска.

## Подключение

| | Claude Code | Codex |
|---|---|---|
| Настройки в репо | `apps/<приложение>/.claude/settings.json` — marketplace `blind-local` и плагин `blind-<приложение>@blind-local` | `.agents/plugins/marketplace.json` в корне, `apps/<приложение>/.codex/config.toml` включает плагин |
| Как читаются настройки | только из папки запуска | слоями от корня до папки запуска |
| Первый запуск | подтвердить доверие к папке проекта | один раз добавить marketplace (см. ниже) и установить плагин приложения |
| Откуда читает | прямо из `.ai-core` | из своей копии в `~/.codex/plugins/cache/blind-local/<плагин>/<version>/` |
| Применение правок | новая сессия или `/reload-plugins` | перезапуск приложения |
| Вызов | `/blind-client:<skill>` | `$<skill>` |

Добавить marketplace в Codex — через раздел плагинов приложения или в `~/.codex/config.toml`:

```toml
[marketplaces.blind-local]
source_type = "local"
source = "<путь к репозиторию>"
```

> **Codex не подхватил правки** после перезапуска — поднять `version` в `.ai-core/<приложение>/.codex-plugin/plugin.json` или переустановить плагин. Проверка: сравнить папку кэша с `.ai-core/<приложение>/skills`.

## Как писать skill

1. `name` в frontmatter совпадает с именем папки.
2. `description` конкретно говорит, когда применять skill, и не пересекается с другими skills — по нему агент выбирает skill.
3. `SKILL.md` короткий: контекст, порядок работы, ключевые правила, проверка результата. Подробности — в `references/`.
4. Правила проекта не копируются в skill — skill ссылается на `docs`, `AGENTS.md` и файлы проекта. Пути должны существовать.
5. Внешние материалы пересказываются, не копируются. Источник, что взято и лицензия — в `references/sources.md`.
6. Сторонние установщики, hooks и скрипты не запускаются и не переносятся без согласования.
7. Визуальная проверка — по правилу из `AGENTS.md`.
8. Неготовый skill помечается как заготовка в `description` и в тексте и говорит агенту, что делать до сборки.

## Когда обновлять

Агент **предлагает** обновить skill, если:

1. skill ссылается на то, чего больше нет или что изменилось;
2. skill расходится с кодом, `docs` или `AGENTS.md`;
3. принято новое решение, которое влияет на дальнейшую работу;
4. повторяется ошибка, которую skill должен был предотвратить;
5. начинается работа в области, где skill отсутствует или помечен как заготовка.

Правила:

1. Skills не меняются молча в рамках другой задачи — сначала коротко объяснить, что и зачем, и получить согласие.
2. Изменение `docs` и связанного skill делается согласованно.
3. После изменения skills агент напоминает обновить плагин в Codex.
4. Добавили, переименовали или удалили skill — проверить ссылки на него в других skills и в `AGENTS.md`.
