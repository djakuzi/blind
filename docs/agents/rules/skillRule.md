# Правила Skills

Раздел описывает, где лежат agent skills проекта, как они подключаются к Claude Code и Codex, как их писать и когда обновлять.

Skill — папка с файлом `SKILL.md` (инструкция для coding agent) и, при необходимости, дополнительными материалами. Агент сам подключает skill, когда задача подходит под его описание, или по явному вызову.

## Где лежат skills

Единственный источник — `.ai-core`. Он оформлен как плагин `blind`:

```text
.ai-core/
├── .claude-plugin/
│   ├── plugin.json        - манифест плагина для Claude Code
│   └── marketplace.json   - локальный marketplace blind-local
├── .codex-plugin/
│   └── plugin.json        - манифест плагина для Codex
└── skills/
    └── <skill-name>/
        ├── SKILL.md       - главный файл skill
        ├── references/    - подробности, читаются по необходимости
        └── tools/         - вспомогательные файлы, если нужны
```

Skills не копируются в `.claude`, `.agents` или `.codex`. Там лежат только настройки подключения.

## Подключение

### Claude Code

- `.claude/settings.json` регистрирует marketplace `blind-local` из `./.ai-core` и включает плагин `blind@blind-local`.
- При первом открытии проекта нужно подтвердить доверие к папке, иначе marketplace не подключится.
- Плагин читается из `.ai-core` напрямую, без копии. Изменения применяются в новой сессии или после `/reload-plugins`.
- Skills вызываются с префиксом плагина: `/blind:ui-ux-design`.

### Codex

- `.agents/plugins/marketplace.json` описывает marketplace `blind-local` с плагином из `./.ai-core`.
- `.codex/config.toml` включает плагин `blind@blind-local` для проекта.
- Marketplace нужно один раз добавить в Codex на своей машине: через раздел плагинов приложения или записью в `~/.codex/config.toml`:

```toml
[marketplaces.blind-local]
source_type = "local"
source = "<путь к репозиторию blind>"
```

После этого плагин «Blind Skills» устанавливается из раздела плагинов.

> **Примечание.** Codex работает не с `.ai-core`, а с копией плагина в `~/.codex/plugins/cache/blind-local/blind/<version>/`. После изменения skills нужно перезапустить приложение. Если изменения не подхватились — поднять `version` в `.ai-core/.codex-plugin/plugin.json` или переустановить плагин в разделе плагинов. Проверить, что копия обновилась, можно сравнением папки кэша с `.ai-core/skills`.

## Как писать skill

1. Папка `skills/<skill-name>/`, в `SKILL.md` frontmatter `name` совпадает с именем папки.
2. `description` объясняет, когда применять skill. По нему агент решает, подключать ли skill, поэтому описание должно быть конкретным и не пересекаться с другими skills.
3. `SKILL.md` короткий: контекст, порядок работы, ключевые правила, как проверить результат. Подробности — в `references/`.
4. Правила проекта не копируются в skill. Skill ссылается на `docs/`, `AGENTS.md` и реальные файлы проекта.
5. Пути к файлам проекта в skill должны существовать. При переносе файлов проверяй ссылки в skills.
6. Если skill собран с использованием внешних материалов, в `references/sources.md` указываются источник, что взято и лицензия. Внешний текст пересказывается и адаптируется, а не копируется.
7. Сторонние установщики, hooks и скрипты из внешних skills не запускаются и не переносятся без согласования с пользователем.
8. Визуальная проверка в skills выполняется по правилу «Визуальная проверка» из `AGENTS.md`.
9. Skill, который ещё не готов, помечается как заготовка в `description` и в тексте и объясняет агенту, что делать до его сборки.

## Когда обновлять skills

Агент предлагает обновить skill, если:

- skill ссылается на файл, папку или правило, которых больше нет или которые изменились;
- skill расходится с кодом, `docs/` или `AGENTS.md`;
- пользователь принял новое решение или соглашение, которое должно влиять на будущую работу;
- агент заметил повторяющуюся ошибку, которую skill должен был предотвратить;
- для области задачи skill отсутствует или помечен как заготовка, а работа в этой области начинается.

Правила:

1. Агент не меняет skills молча в рамках другой задачи. Он кратко описывает, что и почему стоит обновить, и делает это после согласия пользователя.
2. Если обновление skill следует из изменения `docs/`, skill и документацию обновляют согласованно.
3. После изменения skills агент напоминает, что Codex нужно обновить по примечанию из раздела «Codex».
4. При добавлении, переименовании или удалении skill проверяются ссылки на него в других skills и в `AGENTS.md`.
